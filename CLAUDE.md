# gs-frontend — веб-фронт Goodsurfing

- **`apps/web`** — сайт и админка (Next.js 16, App Router, Tailwind 4, Radix). Его правила — `apps/web/CLAUDE.md`, читать перед любой работой там.
- **`packages/api`** — типизированный клиент API, типы генерируются из OpenAPI бэкенда.
- **`e2e/`** — сквозные тесты (Playwright) против стейджа; корневой `package.json` — только для них.
- **`public/locales`** — словари ru/en/es, при сборке копируются в новый фронт (`apps/web/scripts/copy-locales.mjs`).

Старое SPA (React + Vite, корень `src/`) удалено 05.11.2026 (GS-222): весь сайт с 03.11, админка с 04.11 и служебное (robots, карта сайта, старые адреса, отчёты НКО) с 05.11 — в новом фронте.

Ветки: PR → `develop` (деплой на стейдж) → релизный PR `develop` → `master` → тег `v*.*.*` → прод. При релизе вместе с бэкендом фронт выкатывается раньше бэкенда, если в PR не сказано иначе.

## Проверки перед коммитом

Новый фронт (`apps/web`):
```bash
npm run lint && npm run typecheck && npm test && npm run build
```

E2E (`e2e/`, Playwright) гоняются против стейджа после выкатки (`e2e-staging.yml`); локально нужен токен стенда — без него хотя бы `npm ci && npm run e2e:typecheck && npx playwright test --list` в корне.

## Особенности

- Админка (`/admin…`) — внутренний инструмент: не переводить на en/es, функциональность важнее точного вида.
- Зелёные кнопки-призывы — цвет `accent-host` `#02CC9B` (не `success` `#58B893`, он для прогресс-баров и иконок).
- Даты из API строками `d.m.Y` — разбирать явно, не `new Date(строка)`.
- Адреса — только через хелперы маршрутов (`apps/web/src/lib/routes.ts`), не склеивать строки руками.

## Общие правила Goodsurfing (одинаковые во всех репозиториях)

Код пишут только агенты, людей-разработчиков нет, поэтому качество держится на типах, контрактах и автотестах, а не на ревью. Владелец проекта ставит задачи и принимает решения.

**Процесс**
- Любое изменение — через PR из своей ветки. Прямо в `master`/`main`/`develop` не пушить, без исключений.
- Заголовки PR, сообщения коммитов, комментарии в коде и документация — по-русски.
- В коммитах, PR, коде, документации и тестовых данных — никаких упоминаний ИИ, ассистентов, агентов и названий моделей; без строк `Co-Authored-By` и подписей «сгенерировано …».
- Перед коммитом — линт и тесты репозитория (команды ниже). PR с красным CI не считается готовым.
- PR не мержить самостоятельно, если владелец явно не сказал; в прод (`master`/тег) — только по явному согласию владельца.
- Одна задача — один PR. Попутные находки — описать в PR, не чинить молча.
- Секреты (пароли, токены, ключи, DSN, `.env.local`) в репозиторий не коммитить.

**Задачи**
- Трекер — Linear, команда **GS**. Новые задачи не создавать (лимит бесплатного тарифа); вопрос или находку — комментарием к ближайшей по смыслу задаче.
- Юридические риски (ФЗ и т. п.) — максимум одна строка упоминания в PR, не повод менять план.

**Окружения**
- **staging** — https://staging.goodsurfing.org, API https://api-staging.goodsurfing.org. Деплой — мерж в `develop` (у gs-frontend и gs-backend). Ночью (≈01:10–06:55 МСК) стенд выключен — это норма. Данные — обезличенная копия прода, обновляется каждую ночь.
- **prod** — https://goodsurfing.org, API https://api.goodsurfing.org. Прод всегда = `master`, выкатывается тегом `v*.*.*`.
- Прод-данные и прод-окружение не трогать без явного «да» владельца. Разрушающие эндпоинты (`/api/test/reset` и т. п.) для проверки не вызывать — защиту проверять тестами.

**Оплата — критичный функционал**
- Платежи (ЮKassa), членство, пожертвования и сборы меняются только вместе с тестами (в gs-backend — `YookassaFullFlowFunctionalTest`) и проверкой живым тестовым платежом на стейдже.
- Платёжный провайдер может смениться — держать его за интерфейсом, без завязки на ЮKassa в бизнес-логике.
- Возвратов нет (`refund.succeeded` не включаем).

**Медленный интернет и слабые телефоны** (решение владельца 04.11.2026 — учитывать всегда)
- Всё делается с расчётом на медленный мобильный интернет. Картинки — нужного размера (превью `small`/`medium`, а не оригинал), ниже первого экрана — ленивая загрузка, место под картинку зарезервировано, пока грузится — заглушка. У данных всегда есть состояния загрузки, ошибки и пустого.
- Ответы API — постранично и без лишних полей; тяжёлое (письма, обработка картинок, внешние сервисы) не задерживает ответ.
- Новое на сайте и в приложении проверяется на эмуляции медленной сети (Playwright CDP: 50 КБ/с, задержка 400 мс); в PR — что пользователь видит в первые секунды.

**Договорённости по API**
- Даты бэкенд отдаёт строками `d.m.Y` / `d-m-Y` — не оборачивать в `new Date()` без разбора.
- Адреса сайта: русский без префикса (`/membership`), en/es — с префиксом (`/en/membership`), `/ru/…` → 301.
