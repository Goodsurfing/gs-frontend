# apps/web — новый веб-фронт Goodsurfing

Эпик GS-212: веб-фронт переехал сюда целиком — публичная часть и кабинеты (03.11.2026), админка (04.11), служебное старого SPA (05.11). Старое SPA удалено (GS-222); «как у старого сайта» ниже — про внешний вид, сверять со скриншотами и git-историей.

## Главное правило: внешний вид как у старого сайта, внутри — заново

- Пользователь не должен заметить смену движка: цвета, шрифты, отступы, расположение, адаптив, тексты и адреса — как сейчас.
- Код, вёрстка, SCSS и MUI старого фронта **не переносятся**. Старый код — справочник по поведению, не источник для копирования.
- Внешний вид проверяется машинно: визуальные эталоны `e2e/visual` (см. `e2e/README.md`). Осознанные изменения внешнего вида — только с согласия владельца, со скриншотами «до/после» в PR.
- Кривое поведение старого сайта исправляем; заметное пользователю — описывать в PR.

## Стек и решения

- **Next.js 16, App Router, React 19, TypeScript strict** (`noUncheckedIndexedAccess`). По умолчанию серверные компоненты; `"use client"` — только там, где нужна интерактивность.
- **Стили — Tailwind CSS 4 на токенах** из `src/app/globals.css` (`@theme`): значения сняты со старого фронта (`src/app/styles` в корне). В компонентах — только классы на токенах, без «магических» цветов и размеров. Новый токен — в `@theme`, с комментарием, откуда значение.
- **Совпадение с версткой старого сайта:** точки перелома — `down-xl/lg/md/sm/xs` (max-width 1180/992/768/576/480, как `@media` старого фронта); межстрочные интервалы задавать в процентах, как в старом SCSS (Chrome округляет `%` и безразмерные значения по-разному); `antialiased` не включать.
- **Доступные примитивы — Radix UI** (меню, модалки, выпадающие списки). У каждого поля есть `<label>`, у кнопок — понятное имя, модалки — `role="dialog"`. E2E ищут элементы по роли и подписи — без этого тесты не пройдут.
- **i18n:** у русского префикса в адресе нет (`/payment-security-policy`), у en/es есть (`/en/…`, `/es/…`) — решение владельца 29.10.2026; `/ru/…` отвечает 301 (`src/proxy.ts`), русские адреса внутри переписываются на маршрут `[locale]=ru`. Адреса строить только через `src/lib/routes.ts` и `withLocale` (`src/i18n/config.ts`); те же правила в старом SPA — `src/shared/config/routes/localePath.ts`. Словари словари общие со старым фронтом (`public/locales`, копируются при сборке скриптом `scripts/copy-locales.mjs`). Перевод на сервере: `getTranslator(locale, namespace)` из `src/i18n/dictionary.ts`, ключи те же, что в старом фронте.
- **API:** только через `@goodsurfing/api` (`packages/api`): типы генерируются из OpenAPI бэкенда, клиент `createApiClient`. Ручных типов ответов API не писать. Даты бэкенд отдаёт строками `d.m.Y` — не оборачивать в `new Date()` без разбора.
- **SEO:** у каждой публичной страницы `generateMetadata` (title, description, og, canonical, hreflang ru/en/es + x-default); sitemap отдаёт бэкенд (`/sitemap.xml`).
- **Статика — под `/web/`** (`public/web/{fonts,icons,images}`); в корне `public` только то, что живёт по старым адресам: `favicon.png`, `og-image.jpg`, `robots.txt` и отчёты НКО `assets/docs/npo/*` (на них ссылаются письма и страница оплаты).
- **Кто вошёл — в браузере** (`components/session/SessionProvider.tsx`): публичные страницы статические (ISR) и одинаковые для всех, блок пользователя в шапке дорисовывается после запроса профиля с cookie входа (GS-218). Если cookie нет, берётся токен из localStorage (так хранило вход старое SPA — у вошедших до переезда он ещё там); выход очищает оба. Язык вошедшего сохраняется через `PATCH /api/v1/profile/locale` (не `PATCH /profile` — тот перезаписывает профиль и удаляет аватар). Кабинет (будущие страницы) читает cookie на сервере.
- **Битые картинки** подменяются заглушкой `/web/images/placeholder-missing.svg` встроенным скриптом в `[locale]/layout.tsx` (как глобальный обработчик старого SPA).
- **404:** неизвестные адреса — `app/global-not-found.tsx` (язык из заголовка `x-gs-locale`, его ставит `src/proxy.ts`). `[locale]/not-found.tsx` не заводить: Next вкладывает его в данные каждой страницы и рисует 404 от `notFound()` только в браузере. Страница с данными, которых нет (вакансия не найдена), рисует сообщение старого фронта внутри каркаса и `noindex` в метаданных (решено при переносе `/offers/:id`).
- **Персональное на общих страницах:** страница кэшируется одинаковой для всех (данные с сервера — анонимно); то, что зависит от вошедшего (откликнуться, редактировать, оставить отзыв), браузер дозапрашивает с токеном из `useSession()` (пример — `components/offer/OfferViewer.tsx`).
- **Ошибки:** недоступный API → оболочка страницы, не 500. Исключение — страницы с параметром в адресе и кэшем (`/offers/:id`, `/organizations/:id`, статьи и т. п.; не `/fundraise/:id` — там собранная сумма должна быть свежей; `generateStaticParams` → `[]` + `revalidate`): при сбое API они бросают `ApiUnavailableError` (`lib/apiUnavailable.ts`), чтобы экран ошибки не попал в кэш — Next отдаёт прошлую удачную копию, а без неё рисует `[locale]/error.tsx`. Ответ 4xx — «не найдено», это не сбой. `dynamicParams = false` в `[locale]/layout.tsx` не ставить — он делает такие страницы 404. Ошибки сервера и браузера — в Bugsink через `@sentry/nextjs` (`src/instrumentation*.ts`, общие настройки `src/lib/errorTracking.ts`: без ПДн, без трассировки, тег `app=web`, релиз `web-…`). DSN — переменная репозитория `SENTRY_DSN` при сборке; без неё сбор выключен.
- **Метрика:** `components/analytics/YandexMetrika.tsx`, счётчик старого фронта, только при `NEXT_PUBLIC_YANDEX_METRIKA_ID` (задавать для прода; на стенде не задан, чтобы не портить статистику). Переходы внутри приложения засчитываются через `ym(..., 'hit')`.

## Как это работает на стенде

- Образ: `apps/web/Dockerfile` (контекст — корень репозитория), standalone-сервер Next на порту 3100, `/healthz` для проверок, ~40 МБ памяти в простое. Кэш страниц (ISR) живёт в контейнере и пустеет при каждом его пересоздании — после выкатки `deploy-web-*.yml` прогревает его в фоне по sitemap (журнал `/tmp/gs-cache-warmup.log` на VM); после ручного `docker compose up -d web` прогрев запускать той же командой.
- **Маршрутизация:** с 05.11.2026 весь домен — новому фронту (роутеры `web-all` и `web-rest`, `gs-infra/envs/{staging,prod}/cloud-init.yaml`; там же middleware `hsts-only` и `web-healthz`); контейнер старого SPA убран. Неизвестные адреса — настоящая 404. Старые адреса: `*-personal`, `/offers/index`, `/about`, `/about-nko`, `/offers` — 301 в `src/proxy.ts` (`lib/legacyRedirects.ts`); `/offers/host/:id` и `/blog/article/:id` переводит бэкенд по базе — `proxy.ts` проксирует их на API. Карта сайта `/sitemap*.xml` — rewrite на бэкенд (`next.config.ts`), `robots.txt` и отчёты НКО `/assets/docs/npo/*` — в `public`. Роутер `web-canary` (cookie `gs_web=1`) и `/web/preview` остались от переезда и ничего не меняют.
- **Перенесённые страницы:** публичные — `/payment-security-policy`, `/rules`, `/privacy-policy`, `/npo`, `/find-job`, `/our-team`, `/ambassadors`, `/about-project`, `/journals`, `/news`, `/blog`, `/offers-map`, `/` (главная), `/become-host`, `/categories`, `/video`, `/news/:slug`, `/blog/:slug`, `/journals/:slug`, `/video/:id`, `/feedback`, `/offers/:id`, `/organizations/:id`, `/volunteers/:id`, `/academy-main`, `/academy-course/:id`, `/academy-lesson/:id`, `/donation-reports`, `/donation-rating`, `/fundraise/:id`, `/donation/pay/:id`, `/donation/success/:id`, `/donation/fail/:id`, `/membership`, `/payment`, `/payment/success`, `/payment/fail`, `/signin`, `/signup`, `/reset-password`, `/reset-password-verify`, `/confirm-email`, `/confirm-email-success`, `/confirm-error`, `/email-already-confirmed`, `/email-expired`, `/verify-email`, `/verify-email-hash/:hash`, `/unsubscribed`, `/donation-map`; кабинеты и сообщения — см. ниже; всё — и с `/en/…`, `/es/…` (GS-219). Админка — тоже здесь (с 04.11.2026, см. ниже).
- **Кабинет** (`components/cabinet`): каркас `CabinetShell` — лента соцсетей, шапка, меню раздела (`lib/cabinetMenus.ts`), гость → вход, `need="host"|"volunteer"` → выбор роли. Данные кабинета — в браузере с токеном из `useSession()` или cookie входа (на проде с 04.11.2026). Поля форм — `components/form/fields.tsx`, сообщения и переключатель — `ui/Toast.tsx`, подтверждение — `ui/ConfirmDialog.tsx`, загрузка файлов — `lib/uploadMedia.ts`. `/host`, `/volunteer`, `/profile` без продолжения ведут на главную раздела.
  - Профиль: `/profile/info`, `/profile/preferences`, `/profile/role`, `/profile/reset-password`, `/profile/privacy`.
  - Волонтёр (`need="volunteer"`, меню — `lib/volunteerMenu.ts`): `/volunteer/volunteer-dashboard`, `/volunteer/notes`, `/volunteer/review`, `/volunteer/skills`, `/volunteer/gallery`, `/volunteer/articles`, `/volunteer/articles/:id`, `/volunteer/create-article` (редактор — tiptap 3, `cabinet/volunteer/articles/ArticleEditor.tsx`), `/volunteer/subscribers`, `/volunteer/donations`; `/favorite-offers` (`PublicShell` + `RequireUser`, сердечко — `components/offers/useFavoriteOffers.ts`).
  - Организатор (`need="host"`, меню `hostMenu`, `fitContent` — колонка по высоте содержимого): `/host/info`, `/host/team`, `/host/gallery`, `/host/video`, `/host/review`, `/host/host-dashboard`, `/host/notes` (карточка заявки — `cabinet/host/ApplicationCard`, смена статуса — `useApplicationStatus`), `/host/my-offers`, `/host/donations`, `/host/donation-rating`; без меню кабинета — `/host/register`.
  - Мастер вакансии (`components/offer-wizard`, шаги — `lib/offerWizard.ts`, последние шаги — `lib/offerWizardFinish.ts`): `/offers/{welcome,where,when,who-needs,description,what-to-do,conditions,finishing-touches}/:id`.
  - Мастер сбора (`components/fundraise-wizard`, тексты — `lib/fundraiseWizard.ts`, меню — `fundraiseMenu`): `/fundraise/welcome/:id`, `/fundraise/{where,when,amount,description,auto-messages}/:id`; голый `/fundraise` → `/host/donations`. Формы «Где» и «Описание» общие с мастером вакансии (`WhereEditor`, `DescriptionEditor`).
- **Админка** (`components/admin`, страницы `app/[locale]/admin/(panel)/…`, GS-221, с 04.11.2026): только по-русски, внешний вид свой (решение владельца — функции старой админки, вид не важен). Каркас `AdminShell` (меню `lib/admin/menu.ts`; права — пробный запрос `GET /admin/v1/user`, не администратора — на `/admin/sign-in?denied=1`), список по конфигу `AdminList` (фильтры, сортировка, пагинация в адресе), карточка по конфигу `AdminForm` (json/multipart, `type: "custom"`), правка по шагам `StepsEditor` (вакансии, сборы), поля `admin/fields.tsx`, запросы `lib/admin/api.ts` (`/admin/v1`, `errorText` разбирает ошибки полей). Сводка — `GET /admin/v1/dashboard` (gs-backend). Ловушки API: PATCH пользователя и организации перезаписывает запись целиком (слать все поля); текст `null` → `""` («should not be null»); у старых пользователей навыки бывают `null`; тексты курсов и «О проекте» на сайте — простой текст, не HTML. Проверка изменений: сохранить без правки и сравнить GET до/после.
- **Сообщения** (`components/messenger`, `lib/messenger.ts`): `/messenger`, `/messenger/:id`, `/messenger/create/:offerId` (отклик на вакансию), `/messenger/create?recipientVolunteer=…|recipientOrganization=…` (первое сообщение) — одна страница `[[...slug]]`, переход между чатами без перезагрузки. Новые сообщения — одна подписка Mercure (токен старого SPA из localStorage), без токена — опрос раз в 20 секунд.
- **Подводный камень SSR:** на сервере `usePathname()` отдаёт русский адрес с внутренним `/ru` (rewrite в `proxy.ts`), в браузере — без него. Сравнивать адреса только через `normalizePath` / `isSamePage` (`lib/currentPage.ts`), иначе React #418 (так было с меню кабинета организатора).
- **Проверка личного:** с localhost в обычном браузере не проверить (CORS стейджа); для сверки `scripts/visual-compare.mjs --login почта:пароль` входит на обеих страницах и запускает браузер без CORS, e2e — на стейдже.

## Команды

```bash
cd packages/api && npm ci && npm run generate   # типы API со стейджа (или OPENAPI_SOURCE=путь/к/openapi.json)
cd apps/web && npm ci
npm run dev        # http://localhost:3100/ru
npm run lint && npm run typecheck && npm test && npm run build
```

## Порядок переноса раздела

1. Страница собирается из компонентов дизайн-системы, данные — на сервере через `@goodsurfing/api`, `generateMetadata`.
2. Тексты сверены со старым сайтом: `node scripts/text-compare.mjs --old https://staging.goodsurfing.org/ru/… --new http://localhost:3100/ru/…` (на ru/en/es) — неверный ключ словаря даёт доли процента пиксельной разницы и иначе незаметен.
3. Внешний вид сверен со старым сайтом на 390/768/1280: `node scripts/visual-compare.mjs --old https://staging.goodsurfing.org/ru/… --new http://localhost:3100/ru/… --part имя=селектор`. Остаток в доли процента при совпадающих координатах элементов — сглаживание из‑за дробного начала элемента на странице, это норма; разница в размерах или координатах — нет.
4. E2E раздела (`e2e/tests`) зелёные против нового фронта (cookie `gs_web=1`), визуальное сравнение с эталоном старого — в пределах допуска.
5. Для оплаты — живой тестовый платёж на стейдже.
