# E2E-тесты (Playwright)

Сетка, по которой проверяется сайт и принимается новый фронт (эпик GS-212, задача GS-214). Тесты идут против стенда — по умолчанию стейдж, данные не очищаются.

## Запуск

```bash
npm run e2e                                   # вся сетка против стейджа
npx playwright test e2e/tests/public-pages.spec.ts --project=vol
E2E_BASE_URL=https://… E2E_API_URL=https://… npm run e2e   # другой стенд
```

- **Учётные записи.** `global-setup.ts` входит под vol@test.com и host@test.com и сохраняет сессии в `e2e/.auth/`. Ночной restore стейджа пересоздаёт этих пользователей. Сценарии, которые меняют состояние, создают одноразовых пользователей через `/api/test/create-user`.
- **Почта.** Письма стейджа уходят в Mailpit (`support/mailpit.ts`). Нужны `MAILPIT_USER` и `MAILPIT_PASSWORD`: в CI это секреты репозитория, локально — `set -a; . ~/.config/goodsurfing/mailpit-staging.env; set +a`. Без них сценарии с письмами пропускаются.
- **Служебные эндпоинты.** `/api/test/*` стейджа требуют заголовок `X-E2E-Token` (`support/testApi.ts`): стейдж публичный. Токен — `E2E_TOKEN`; в CI это секрет репозитория, локально — `set -a; . ~/.config/goodsurfing/e2e-token.env; set +a`. Без него сценарии с одноразовыми пользователями пропускаются.
- **`/api/test/reset`** стирает данные стенда. Вызывается только при `E2E_RESET=1` и только на локальном стенде, никогда на стейдже.
- **CI.** `.github/workflows/e2e-staging.yml` запускает сетку после каждого деплоя на стейдж и каждое утро. Падение — сообщение в Telegram и запрет выкатки в прод.

## Что покрыто

| Файл | Что проверяет |
|---|---|
| `tests/public-pages.spec.ts` | Все публичные страницы у гостя открываются без JS-ошибок и экрана ошибки; 404; языки |
| `tests/cabinet-pages.spec.ts` | Все страницы кабинета волонтёра (16) и хоста (20) открываются без ошибок и не выкидывают на вход; гостя личные страницы уводят на вход |
| `tests/admin-pages.spec.ts` | Одноразовый администратор: 23 раздела админки, карточки пользователя и организации; обычного пользователя в админку не пускает |
| `tests/vacancy-wizard.spec.ts` | Хост: «Добавить вакансию» → черновик → все 8 шагов мастера открываются; черновик удаляется |
| `tests/profile.spec.ts` | Одноразовый пользователь: фамилия и «О себе» сохраняются и видны после перезагрузки; аватар загружается и привязывается |
| `tests/favorites.spec.ts` | Одноразовый пользователь: сердечко на карте → вакансия в «Избранном» → убрать |
| `tests/auth.spec.ts` | Регистрация → письмо → подтверждение почты → вход; неверный пароль; сброс пароля по ссылке из письма |
| `tests/seo.spec.ts` | Мета-теги, hreflang, sitemap |
| `tests/offers-map.spec.ts` | Карта вакансий: интерактивность |
| `tests/application-flow.spec.ts` | Отклик волонтёра, принятие и отклонение хостом, переписка |
| `tests/payment.spec.ts` | Оплата членства тестовой картой ЮKassa через API-чекаут, активация |
| `tests/payments-ui.spec.ts` | Через интерфейс: международный клуб («Стать участником» → ЮKassa → членство и строка в профиле); пожертвование в сбор (волонтёр → «Поддержать» → 100 ₽ → ЮKassa → в списке сбора) |
| `tests/smoke.spec.ts` | Вход волонтёра и хоста |

Поля ищутся по подписи (`getByLabel`), кнопки — по роли и имени: так одни и те же тесты пройдут и на новом фронте. Одноразовые пользователи — `support/session.ts`, оплата тестовой картой и повтор уведомления ЮKassa — `support/yookassa.ts`.

Общая проверка «страница работает» — `support/pageCheck.ts`: ответ < 400, нет JS-ошибок и экрана ошибки, не 404, есть контент. Список публичных страниц — `support/publicPages.ts`. Он общий для функциональных проверок и визуальных эталонов. Новую публичную страницу добавлять туда.

## Визуальные эталоны

Новый фронт должен внешне совпадать со старым. Данные стейджа каждую ночь заменяются копией прода, поэтому эталоны не хранятся в git. Их снимают со старого фронта прямо перед сравнением, на тех же данных:

```bash
# 1. Эталон со старого фронта (31 страница × 390/768/1280 px × ru/en)
E2E_VISUAL=1 E2E_BASE_URL=https://staging.goodsurfing.org \
  npx playwright test --project=visual --update-snapshots

# 2. Сразу же — сравнение нового фронта с эталоном
E2E_VISUAL=1 E2E_BASE_URL=https://<новый фронт> npx playwright test --project=visual
```

- Снимки сохраняются в `e2e/visual/__snapshots__/`, различия — в `test-results/` (`*-diff.png`).
- Допуск: 2 % пикселей на страницу.
- То, что меняется само по себе (карты, видео, автопрокручиваемые слайдеры, отзывы на главной), закрыто маской. Анимации появления (AOS) перед снимком выключаются.
- Если элемент меняется между двумя прогонами одного и того же фронта, его нужно добавить в маску (`DYNAMIC` в `visual/visual.spec.ts`) через `data-testid`: в сборке имена CSS-классов хэшируются.
