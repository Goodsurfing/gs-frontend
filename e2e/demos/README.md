# Демо фич для релиза

Короткое видео и скриншоты сценария фичи на стейдже — чтобы перед релизом и после него было видно, как фича работает, без чтения кода.

Один файл `<фича>.demo.ts` на фичу. Каждая сцена записывается в отдельный файл видео, потом сцены склеиваются в один mp4. Внизу экрана — подписи, что происходит. Результат — `e2e/demos/output/<фича>/` (не в git):

- `<фича>.mp4` — видео, около 1–2 минут;
- `shots/*.png` — скриншоты ключевых мест, по порядку.

## Запуск

```bash
set -a; . ~/.config/goodsurfing/e2e-token.env; . ~/.config/goodsurfing/mailpit-staging.env; . ~/.config/goodsurfing/e2e-users.env; set +a
npx playwright test -c e2e/demos/playwright.demo.config.ts membership-duo
e2e/demos/make-video.sh membership-duo
```

Нужны `E2E_TOKEN` (одноразовые пользователи), `MAILPIT_USER`/`MAILPIT_PASSWORD` (письма), `ffmpeg`.

## Как писать демо

- Пользователи — одноразовые (`createSession`), с понятными именами (Анна, Борис), чтобы на видео было ясно, кто есть кто.
- Каждый шаг — `say(page, 'что происходит и зачем')`: одна фраза простыми словами, 3–4 секунды на экране.
- Ключевые места — `shot(page, FEATURE, 'NN-название')`; потом эти скриншоты идут в документ релиза.
- Подготовка, которую смотреть не нужно (ожидание кеша, повтор уведомления ЮKassa), — между сценами, она в видео не попадает.
- Оплата — только тестовой картой на стейдже.

## Документ релиза

Блок фичи в документе релиза (Google Drive, папка «Гудсёрфинг — документы»):

1. что это и зачем;
2. кто видит и где;
3. видео и скриншоты;
4. как попробовать на стейдже;
5. что сделать при релизе.
